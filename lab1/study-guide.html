2. Предобработка данных

Разделение: 60 / 20 / 20

Зачем 3 части, а не 2? Train — для подгонки весов. Validation — смотрим loss после каждой эпохи, чтобы вовремя остановить при переобучении. Test — трогаем один раз в конце, чтобы получить честную оценку. Если тестировать на val — это «утечка» информации: мы подбирали гиперпараметры глядя на val, он уже нечестный.

StandardScaler: зачем нормализовать

scaler = StandardScaler()
X_train = scaler.fit_transform(X_train)   # вычислить μ, σ и применить
X_val   = scaler.transform(X_val)         # применить ТЕ ЖЕ μ, σ
X_test  = scaler.transform(X_test)        # применить ТЕ ЖЕ μ, σ

Формула: x_scaled = (x - μ) / σ — после неё каждый признак имеет среднее 0 и std 1.

Зачем? Без нормализации st_teff (~5000) доминирует над st_met (~0.01). Градиенты будут огромными по одним осям и крошечными по другим — обучение будет нестабильным и медленным. StandardScaler уравнивает масштабы.
Важно для ответа преподавателю: fit_transform вызываем ТОЛЬКО на train! На val/test — только transform. Иначе мы «подглядываем» в тестовые данные (data leakage) — среднее и std должны быть из обучающей выборки.

Тензоры и DataLoader

X_train_t = torch.tensor(X_train, dtype=torch.float32)  # NumPy → Tensor
y_train_t = torch.tensor(y_train, dtype=torch.long)      # метки — целые числа

Зачем batch_size=32, а не все 614 сразу? Мини-батчи дают стохастический шум в градиентах — помогают выбираться из локальных минимумов. Плюс экономят память. 32 — стандартное значение, хорошо работает для малых датасетов.
Зачем shuffle=True? Без перемешивания модель видит данные в одном порядке и может «запомнить» последовательность вместо паттернов. Shuffle разрушает этот эффект.

3. Архитектура MLP

MLP (Multi-Layer Perceptron) — полносвязная нейронная сеть, где каждый нейрон слоя связан со всеми нейронами предыдущего слоя.

Схема сети [64, 32]

Компоненты каждого слоя — зачем каждый

КомпонентЧто делаетЗачем
nn.Linear(in, out) y = W*x + b Линейное преобразование. Основа нейрона — обучаемые параметры W и b
nn.BatchNorm1d(n) (x - μ_batch) / σ_batch Нормализует выходы по текущему батчу. Ускоряет обучение, стабилизирует градиенты. Бонус: небольшая регуляризация
nn.ReLU() max(0, x) Нелинейность! Без неё вся сеть = одна линейная функция (бесполезна). ReLU — самая быстрая и популярная
nn.Dropout(0.3) Случайно зануляет 30% нейронов при обучении Регуляризация. Сеть не может «полагаться» на один нейрон — вынуждена распределять знания. Борется с переобучением
Почему на выходном слое НЕТ активации? Потому что CrossEntropyLoss в PyTorch уже включает softmax внутри. Если поставить softmax + CrossEntropyLoss — softmax применится дважды, и модель будет считать неправильные градиенты. Это частая ошибка!
Код класса MLP — построчно 
class MLP(nn.Module):
    def __init__(self, inputDim, hiddenShape, outputDim=5,
                 fActivation=nn.ReLU, dropoutRate=0.3):
        super().__init__()         # вызов конструктора базового класса

        # Входной блок: 4 → 64
        self.inputModule = nn.Sequential(
            nn.Linear(inputDim, hiddenShape[0]),   # W: [4×64], b: [64]
            nn.BatchNorm1d(hiddenShape[0]),         # нормализация
            fActivation(),                          # ReLU
            nn.Dropout(dropoutRate),                # dropout 30%
        )

        # Скрытые блоки: 64 → 32 (для [64, 32])
        # Генерируется автоматически: для каждой пары соседних размеров
        self.hiddenModule = nn.Sequential(
            *[nn.Sequential(
                nn.Linear(hiddenShape[i], hiddenShape[i+1]),
                nn.BatchNorm1d(hiddenShape[i+1]),
                fActivation(),
                nn.Dropout(dropoutRate),
            ) for i in range(len(hiddenShape) - 1)]
        )

        # Выходной слой: 32 → 5 (без активации!)
        self.outputModule = nn.Linear(hiddenShape[-1], outputDim)

    def forward(self, x):
        x = self.inputModule(x)    # (batch, 4) → (batch, 64)
        x = self.hiddenModule(x)   # (batch, 64) → (batch, 32)
        x = self.outputModule(x)   # (batch, 32) → (batch, 5) — логиты
        return x
nn.Sequential: контейнер, который пропускает данные через все слои последовательно. Вместо ручного вызова каждого слоя в forward().

4. Forward Pass (прямой проход)

Прямой проход — это путь данных от входа к выходу. Для одного объекта:

Слой 1: z₁ = W₁·x + b₁ → BN(z₁) → a₁ = ReLU(BN(z₁)) → Dropout(a₁) Слой 2: z₂ = W₂·a₁ + b₂ → BN(z₂) → a₂ = ReLU(BN(z₂)) → Dropout(a₂) Выход: z₃ = W₃·a₂ + b₃ → логиты (5 чисел) Loss: L = CrossEntropy(softmax(z₃), y_true)

Пример прохода одного объекта

Вход x = [5400, 0.92, 0.13, 1684]  (raw)
         ↓ StandardScaler
x_scaled = [0.08, -0.12, 0.63, 1.75]  (нормализовано)
         ↓ Linear(4→64): W₁·x + b₁
z₁ = [0.34, -1.20, 0.87, ..., -0.55]  (64 числа)
         ↓ BatchNorm
z₁_bn = [-0.12, -2.1, 0.91, ..., -0.3]
         ↓ ReLU: max(0, x)
a₁ = [0, 0, 0.91, ..., 0]  (отрицательные стали 0)
         ↓ Dropout(0.3): случайно занулить 30%
a₁_drop = [0, 0, 0.91, ..., 0]
         ↓ Linear(64→32): W₂·a₁ + b₂
z₂ = [...32 числа...]
         ↓ BN → ReLU → Dropout
a₂ = [...32 числа...]
         ↓ Linear(32→5): W₃·a₂ + b₃
логиты = [2.1, 5.3, 0.8, -1.0, 0.3]  (5 сырых оценок)
         ↓ softmax (внутри CrossEntropyLoss)
вероятности = [0.04, 0.82, 0.03, 0.01, 0.10]
         ↓ argmax
предсказание = класс 1 (sub_neptune) с вероятностью 82%

5. Backpropagation (обратное распространение ошибки)

Backprop — алгоритм вычисления градиентов функции потерь по всем весам сети. Это сердце обучения нейросети.

Идея в одном предложении

Цепное правило (chain rule): если f = g(h(x)), то f'(x) = g'(h(x)) · h'(x)

Градиент «течёт» назад от loss к каждому весу, умножаясь на локальный градиент каждого слоя

Схема Backprop для нашей сети

Что происходит в коде

for xb, yb in train_loader:       # берём мини-батч (32 объекта)
    optimizer.zero_grad()           # 1. Обнулить градиенты
    loss = criterion(model(xb), yb) # 2. Forward: предсказание → loss
    loss.backward()                 # 3. Backward: вычислить ∂L/∂θ для всех θ
    optimizer.step()                # 4. Update: θ = θ - lr · ∂L/∂θ
СтрокаЧто происходитЗачем
zero_grad() Обнуляет все .grad тензоры PyTorch по умолчанию накапливает градиенты (+=). Без обнуления градиенты будут расти от батча к батчу
model(xb) Вызывает forward() — прогоняет данные через сеть Получает логиты (предсказания)
criterion(...) CrossEntropyLoss считает скаляр loss Одно число — «насколько плохо модель предсказала»
loss.backward() Запускает backprop: chain rule по всему графу Заполняет .grad у каждого параметра — «в какую сторону и насколько сильно двигать»
optimizer.step() Adam обновляет все веса: θ -= lr · grad Фактическое обучение — веса сдвигаются в сторону уменьшения loss
Почему Adam, а не обычный SGD? Adam (Adaptive Moment Estimation) адаптирует learning rate для каждого параметра отдельно. Для параметров с редкими обновлениями — lr больше, для частых — меньше. Плюс использует «инерцию» (momentum). На практике сходится быстрее SGD и менее чувствителен к начальному lr.

6. Векторизация формул

Нейронная сеть обрабатывает не один объект, а батч из 32 одновременно. Все операции — матричные.

Один объект vs батч

Один объект (скалярно)

Для нейрона j слоя l: z_j = Σᵢ (w_ji · a_i) + b_j a_j = ReLU(z_j) 4 входа → 64 нейрона = 256 умножений

Батч (матрично)

Z = X · Wᵀ + b A = ReLU(Z) X: [32, 4] — 32 объекта × 4 признака W: [64, 4] — 64 нейрона × 4 входа Wᵀ: [4, 64] Z: [32, 64] — результат для всех 32 сразу b: [64] — broadcast: добавляется к каждой строке
Зачем векторизация? GPU параллелят матричные операции. Вместо 32 последовательных проходов — одно умножение матриц. Это в 10-100x быстрее. Поэтому batch_size кратен степеням двойки (32, 64, 128) — GPU оптимизированы под эти размеры.

Полный forward pass в матричной форме

Входные данные: X ∈ ℝ^{32×4} Слой 1: Z₁ = X · W₁ᵀ + b₁ (W₁ ∈ ℝ^{64×4}, Z₁ ∈ ℝ^{32×64}) H₁ = BatchNorm(Z₁) A₁ = ReLU(H₁) A₁ = Dropout(A₁, p=0.3) Слой 2: Z₂ = A₁ · W₂ᵀ + b₂ (W₂ ∈ ℝ^{32×64}, Z₂ ∈ ℝ^{32×32}) H₂ = BatchNorm(Z₂) A₂ = ReLU(H₂) A₂ = Dropout(A₂, p=0.3) Выход: Z₃ = A₂ · W₃ᵀ + b₃ (W₃ ∈ ℝ^{5×32}, Z₃ ∈ ℝ^{32×5}) Softmax: P = exp(Z₃) / Σ exp(Z₃) (по оси классов, dim=1) P ∈ ℝ^{32×5} — вероятности для каждого из 32 объектов Loss: L = -(1/32) · Σᵢ log(P[i, yᵢ]) yᵢ — истинный класс i-го объекта

Backward pass в матричной форме

Градиент на выходе: ∂L/∂Z₃ = P - Y_onehot (softmax минус one-hot метка) [32×5] = [32×5] - [32×5] Градиент по W₃: ∂L/∂W₃ = (∂L/∂Z₃)ᵀ · A₂ / batch_size [5×32] = [5×32] · [32×32] / 32 Градиент «назад» по A₂: ∂L/∂A₂ = ∂L/∂Z₃ · W₃ [32×32] = [32×5] · [5×32] Через ReLU (поэлементно): ∂L/∂H₂ = ∂L/∂A₂ ⊙ (H₂ > 0) ← маска: 1 где было > 0, 0 где ≤ 0 [32×32] = [32×32] ⊙ [32×32] ...и так далее до ∂L/∂W₁
Ключевой момент для преподавателя: Градиент через ReLU — это просто маска: где вход был положительный — пропускаем градиент (×1), где отрицательный — обнуляем (×0). Именно поэтому «мёртвые нейроны» — нейроны, которые всегда получают отрицательный вход — перестают обучаться навсегда: через них не проходит градиент.

7. Функции активации

Функция активации вносит нелинейность. Без неё любая глубокая сеть = одна линейная функция (доказательство: композиция линейных функций = линейная функция).

Sigmoid

f(x) = 1 / (1 + e⁻ˣ)
Диапазон: (0, 1)
+ вероятностная интерпретация
- vanishing gradients при |x|>5
- не центрирована (>0)

Tanh

f(x) = (eˣ - e⁻ˣ) / (eˣ + e⁻ˣ)
Диапазон: (-1, 1)
+ центрирована вокруг 0
- vanishing gradients

ReLU

f(x) = max(0, x)
Диапазон: [0, +∞)
+ быстрая, нет насыщения при x>0
+ используется в нашей сети!
- «мёртвые нейроны» при x<0

Leaky ReLU

f(x) = x if x>0, else 0.01x
Диапазон: (-∞, +∞)
+ нет мёртвых нейронов
- нужно подбирать α

ELU

f(x) = x if x>0, else α(eˣ-1)
Диапазон: (-α, +∞)
+ гладкая, нет мёртвых нейронов
- дороже вычислительно (exp)

Swish

f(x) = x · sigmoid(x)
Диапазон: (~-0.28, +∞)
+ гладкая, из исследования Google
- дороже ReLU

Softplus

f(x) = ln(1 + eˣ)
Диапазон: (0, +∞)
+ гладкая аппроксимация ReLU
- нет отрицательных выходов

GELU

BERT, GPT, Transformers
Диапазон: (~-0.17, +∞)
+ стандарт в NLP/LLM
- дорогая (tanh + степени)

Производные (для backprop)

Функцияf(x)f'(x)Особенность
Sigmoidσ(x)σ(x)(1 - σ(x))max = 0.25 при x=0, затухает
Tanhtanh(x)1 - tanh²(x)max = 1 при x=0, затухает
ReLUmax(0,x)1 (x>0), 0 (x≤0)Не затухает! Но 0 при x<0
Leaky ReLUmax(αx, x)1 (x>0), α (x≤0)Всегда ненулевой
Softmaxeᶻⱼ / Σeᶻᵢpⱼ(1-pⱼ) или -pⱼpₖЯкобиан, не скаляр
Почему мы выбрали ReLU, а не Sigmoid/Tanh? 1) ReLU не страдает от vanishing gradients при x>0 (производная = 1, а не ~0 как у sigmoid). 2) Вычислительно дешевле (просто max). 3) Ведёт к разреженным представлениям (часть нейронов = 0) — это неплохая регуляризация. Sigmoid используется только в выходном слое для бинарной классификации (не наш случай).

8. Процесс обучения

model.train() vs model.eval()

РежимDropoutBatchNormКогда
model.train() Активен (случайно обнуляет нейроны) Считает μ, σ по текущему батчу Обучение (внутри цикла по батчам)
model.eval() Выключен (все нейроны работают) Использует накопленные μ, σ Оценка (val, test) и инференс
Зачем переключать? При обучении dropout убирает 30% нейронов — это хорошо для регуляризации. Но при оценке мы хотим использовать всю сеть целиком, чтобы получить лучшее предсказание. Если забыть model.eval() — метрики будут занижены.

torch.no_grad()

model.eval()
with torch.no_grad():    # отключить вычислительный граф
    logits = model(x)    # быстрее, меньше памяти
Зачем? PyTorch по умолчанию строит вычислительный граф для backward(). Это занимает память. При оценке backward() не нужен — no_grad() экономит ~30-50% памяти и ускоряет вычисления.

Полный цикл обучения — построчный разбор

def train_model(model, train_loader, val_loader, epochs, lr):
    criterion = nn.CrossEntropyLoss()       # функция потерь
    optimizer = optim.Adam(model.parameters(), lr=lr)  # оптимизатор
    history = {'train_loss':[], 'val_loss':[], 'train_acc':[], 'val_acc':[]}

    for epoch in range(epochs):             # 100 эпох
        model.train()                       # включить dropout + BN в режиме обучения

        for xb, yb in train_loader:         # по 32 объекта за раз
            optimizer.zero_grad()           # 1) обнулить градиенты
            loss = criterion(model(xb), yb) # 2) forward + loss
            loss.backward()                 # 3) backward — вычислить градиенты
            optimizer.step()                # 4) обновить веса: W -= lr * grad

        model.eval()                        # выключить dropout
        with torch.no_grad():               # отключить граф (экономия памяти)
            t_loss, t_acc = evaluate(model, train_loader, criterion)
            v_loss, v_acc = evaluate(model, val_loader, criterion)

        history['train_loss'].append(t_loss)
        # ... аналогично для остальных метрик

    return history
Почему optimizer.zero_grad() ПЕРЕД каждым батчем? PyTorch накапливает градиенты (складывает новые к старым). Это удобно для accumulation, но обычно нам нужен градиент только текущего батча. Без zero_grad() градиенты предыдущих батчей «загрязняют» текущий.
Порядок шагов (1-2-3-4) — это каноническая последовательность:
1. zero_grad() — очистить
2. forward + loss — предсказать и посчитать ошибку
3. backward() — распространить ошибку назад (заполнить .grad)
4. step() — шагнуть в направлении уменьшения ошибки
Перепутать порядок = сломать обучение.

Функция evaluate() — код оценки

def evaluate(model, loader, criterion):
    loss_sum, correct, total = 0.0, 0, 0
    for xb, yb in loader:
        logits = model(xb)                          # предсказания (без softmax)
        loss_sum += criterion(logits, yb).item() * xb.size(0)  # loss × размер батча
        preds = logits.argmax(dim=1)                # argmax → номер класса
        correct += (preds == yb).sum().item()       # сколько угадали
        total += yb.size(0)                         # сколько всего
    return loss_sum / total, correct / total        # средний loss и accuracy
Зачем loss * xb.size(0)? CrossEntropyLoss по умолчанию возвращает среднее по батчу. Чтобы получить средний loss по всему датасету, нужно: (1) умножить на размер батча → получить сумму; (2) сложить по всем батчам; (3) поделить на общее число объектов. Последний батч может быть неполным (614 % 32 = 6 объектов), поэтому нельзя просто усреднить потери батчей.

Кривые обучения — как читать

Наш результат: train_acc = 53.3%, val_acc = 57.1%, разрыв = -3.8%. Переобучения нет (val даже чуть выше — нормально при dropout). Но accuracy невысокий — задача объективно сложная (классы перекрываются на PCA).

Код оценки на тестовой выборке — разбор

def evaluate_model(model, test_loader):
    model.eval()                                # dropout OFF, BN inference
    all_preds, all_probs, all_labels = [], [], []

    with torch.no_grad():
        for xb, yb in test_loader:
            logits = model(xb)                  # сырые оценки (5 чисел)
            probs = torch.softmax(logits, dim=1).numpy()  # → вероятности
            preds = logits.argmax(dim=1).numpy()          # → номер класса
            all_probs.append(probs)
            all_preds.extend(preds)
            all_labels.extend(yb.numpy())

    return np.array(all_labels), np.array(all_preds), np.vstack(all_probs)
Зачем softmax здесь, если CrossEntropyLoss уже включает softmax? CrossEntropyLoss применяет softmax внутри себя при обучении. Но для ROC AUC нам нужны вероятности отдельно. Поэтому при инференсе мы вычисляем softmax вручную. Это не дублирование — это разные этапы.
argmax(dim=1) — что делает? Для каждого объекта в батче (dim=0 — объекты, dim=1 — классы) находит индекс максимального логита. Логиты = [2.1, 5.3, 0.8, -1.0, 0.3] → argmax = 1 → модель предсказывает класс №1 (sub_neptune_mini_gas).

Как вызываются метрики sklearn

y_true, y_pred, y_prob = evaluate_model(model, test_loader)

accuracy_score(y_true, y_pred)                                    # 0.517
precision_score(y_true, y_pred, average='macro')                  # 0.514
recall_score(y_true, y_pred, average='macro')                     # 0.375
f1_score(y_true, y_pred, average='macro')                         # 0.368
roc_auc_score(y_true, y_prob, multi_class='ovr')                  # 0.728

# classification_report — сводка по КАЖДОМУ классу отдельно

average='macro' — считает метрику для каждого из 5 классов отдельно, потом берёт обычное среднее. Все классы одинаково важны, независимо от размера. Альтернатива 'weighted' учитывает размер класса, но тогда редкие классы почти не влияют на итоговую метрику.
multi_class='ovr' (one-vs-rest) — для каждого класса строится отдельная бинарная ROC-кривая: «этот класс vs все остальные». Потом AUC усредняется. Альтернатива 'ovo' (one-vs-one) считает попарно, но ovr стандартнее.

Softmax и CrossEntropyLoss

Softmax — превращает логиты в вероятности: логиты z = [2.1, 5.3, 0.8, -1.0, 0.3] e^(zⱼ) e^5.3 p(j) = ────────────── , p(2) = ────────────── = 0.82 Σ e^(zᵢ) Σ e^(zᵢ) вероятности = [0.04, 0.82, 0.03, 0.01, 0.10] (сумма = 1) CrossEntropyLoss — штраф за неуверенность: L = -log(p(y_true)) Если истинный класс = 2 (sub_neptune), p(2) = 0.82: L = -log(0.82) = 0.20 (маленький штраф — модель уверена и права) Если бы p(2) = 0.05: L = -log(0.05) = 3.00 (большой штраф — модель ошиблась)

Почему torch.manual_seed(SEED) перед каждой моделью? Инициализация весов случайна. Если не фиксировать seed, разница в результатах может быть от случайной инициализации, а не от архитектуры. Seed гарантирует: разница — только из-за архитектуры.
Что делает sum(p.numel() for p in m.parameters())? m.parameters() итерирует по всем обучаемым тензорам (W, b, γ, β). p.numel() — число элементов в тензоре. Для Linear(4→64): W имеет 4×64 = 256 элементов, b — 64. Сумма — общее число обучаемых параметров модели.

Правило для преподавателя: На малых данных (<1000 примеров) 2-3 слоя обычно оптимальны. Глубокие сети (5+ слоёв) нужны для задач с тысячами/миллионами примеров и сложной иерархической структурой (изображения, текст). Для табличных данных с 4 признаками — «больше» не значит «лучше».

11. Вопросы, которые может задать преподаватель

Зачем нужна функция активации? Что будет без неё?

Без функции активации каждый слой — линейная функция y = Wx + b. Композиция линейных функций = линейная функция: W₂(W₁x + b₁) + b₂ = W₂W₁x + W₂b₁ + b₂ = W'x + b'. То есть вся сеть из 100 слоёв эквивалентна одному линейному слою — бесполезна для нелинейных задач. Активация (ReLU, sigmoid) ломает эту линейность.

Почему на выходном слое нет ReLU / softmax?

PyTorch CrossEntropyLoss включает softmax внутри. Если добавить softmax явно — он применится дважды, и градиенты будут неправильными. Без ReLU, потому что логиты могут быть отрицательными — и это нормально (отрицательный логит = модель считает класс маловероятным).

Что такое BatchNorm и зачем он нужен?

BatchNorm нормализует выходы слоя по текущему мини-батчу: x_norm = (x - μ_batch) / σ_batch, потом масштабирует: y = γ·x_norm + β (γ и β — обучаемые). Зачем: 1) стабилизирует обучение — распределение активаций не «уплывает» между слоями (internal covariate shift); 2) позволяет использовать больший learning rate; 3) слегка регуляризирует (шум от мини-батча).

Зачем Dropout? Как он работает?

При обучении случайно обнуляет нейроны с вероятностью p=0.3. Каждый батч — разная маска. Это заставляет сеть распределять знания между нейронами (не полагаться на один). При eval() dropout выключен, но выходы масштабируются на (1-p), чтобы среднее значение совпадало.

Почему разделение данных именно 60/20/20?

Test (20%) — для честной финальной оценки. Val (20%) — для мониторинга переобучения и подбора гиперпараметров. Train (60%) — всё остальное. При 1024 объектах это 614/205/205. Пропорции стандартные для малых датасетов. При больших данных (>100K) можно 90/5/5.

Что значит stratify при split?

Сохраняет пропорции классов. Если super_jupiter = 5.5% в полном датасете, то и в train = 5.5%, и в test = 5.5%. Без stratify случайная выборка может дать 0% super_jupiter в тесте — и мы не сможем оценить модель на этом классе.

Почему StandardScaler.fit() только на train?

Data leakage. Если fit на всём датасете — среднее и std содержат информацию из тестовой выборки. Модель «подглядывает» в данные, которые должна видеть только при финальной оценке. На практике утечка через scaler обычно мала, но принцип строгий: train определяет всё.

Что такое мёртвые нейроны (dead neurons)?

Нейрон с ReLU, который всегда получает отрицательный вход. ReLU(-x) = 0, и градиент тоже 0. Нейрон перестаёт обучаться навсегда. Причина: слишком большой learning rate сдвигает bias так, что нейрон уходит в отрицательную зону. Решения: Leaky ReLU (малый, но ненулевой градиент при x<0), BatchNorm (центрирует распределение), аккуратный выбор lr.

Почему accuracy невысокий (52%)?

1) PCA показывает: классы сильно перекрываются — объективно сложная задача. 2) Только 4 признака — мало информации для различения 5 классов. 3) Малый датасет (614 train). 4) Дисбаланс: 56 super_jupiter vs 330 sub_neptune. При случайном угадывании (всегда предсказывать sub_neptune) accuracy = 32%. Наши 52% — заметно лучше случайного.

Как считается CrossEntropyLoss с vectorization?

Для батча из N объектов: L = -(1/N) · Σᵢ log(softmax(zᵢ)[yᵢ]), где zᵢ — логиты i-го объекта (вектор из 5), yᵢ — истинный класс. В матричной форме: P = softmax(Z) где Z ∈ ℝ^{N×5}, потом L = -(1/N) · Σᵢ log(P[i, yᵢ]). PyTorch делает это за одну операцию с numerical stability (log-sum-exp trick).

Зачем нужен PCA-график?

PCA (Principal Component Analysis) проецирует 4D-данные на 2D, сохраняя максимум дисперсии. Если на 2D-проекции классы хорошо разделяются — задача простая, даже линейная модель справится. Если перекрываются (как у нас) — задача сложная. PC1 объясняет наибольшую долю дисперсии, PC2 — вторую. Вместе они показывают «главные направления» в данных.
