## 0. Что такое OpenMP за 1 минуту

Программа обычно выполняется **одним потоком** (последовательно). OpenMP позволяет
кусок кода выполнить **несколькими потоками одновременно** — просто добавив строчку-директиву
`#pragma omp ...` перед блоком. Компилятор сам создаёт потоки.

- **Нить (поток)** — независимый «исполнитель». Их несколько, у каждого свой номер `0, 1, 2, …`.
- **Нить-мастер** — нить номер `0`, она всегда есть.
- **Параллельная область** — блок `{ ... }` после `#pragma omp parallel`, который выполняет каждая нить.
- **Общие (shared) переменные** — одни на всех; если несколько нитей пишут в них одновременно,
  получается **гонка данных** (неверный результат). От неё спасают `reduction`, `atomic`,
  `critical`, замки.
- **Локальные (private) переменные** — у каждой нити свои.

### Как компилировать и запускать

**Linux (как в заданиях):**
```bash
g++ -o 1.o 1.cpp -fopenmp      # для C++  (gcc -o 1.o 1.c -fopenmp для C)
./1.o
```
Число нитей задаётся переменной окружения:
```bash
export OMP_NUM_THREADS=4
```

**macOS (здесь нет gcc, но есть libomp от Homebrew):**
```bash
clang++ -Xpreprocessor -fopenmp 1.cpp -o 1.o \
  -I/opt/homebrew/opt/libomp/include \
  -L/opt/homebrew/opt/libomp/lib -lomp
./1.o
```

Основные функции (нужен `#include <omp.h>`):
- `omp_get_thread_num()` — номер текущей нити;
- `omp_get_num_threads()` — сколько нитей сейчас работает;
- `omp_set_num_threads(n)` — задать число нитей;
- `omp_get_wtime()` — текущее время в секундах (для замеров).

## Лаба 1. Введение (файл `1.cpp`)

**Цель:** проверить поддержку OpenMP, научиться печатать номера нитей и задавать их число.

Три части:
1. **Проверка OpenMP** — макрос `_OPENMP` определён, только если включён `-fopenmp`.
   Проверяем через `#ifdef _OPENMP`.
2. **Номера нитей** — внутри `#pragma omp parallel` каждая нить печатает `omp_get_thread_num()`,
   а общее число нитей печатает **только мастер** через `#pragma omp master`.
3. **Число нитей** — `omp_set_num_threads(2)` задаёт 2 нити по умолчанию, а опция
   `num_threads(3)` в конкретной области перебивает это значение на 3.

> **Ответ на вопрос задания:** параллельных областей в программе может быть **сколько угодно**.

Вывод (нити печатают в произвольном порядке — это нормально):
```
OpenMP поддерживается! Версия (_OPENMP) = 202011
Привет от потока номер 2
Привет от потока номер 0
>>> Master: всего потоков = 4
...
Область 1 (num_threads(3)): поток 0
Область 2 (по умолчанию = 2): поток 1
```

## Лаба 2. Суммирование массива (файл `2.cpp`)

**Цель:** просуммировать массив из единиц (правильная сумма = `n`) четырьмя способами
и понять, почему «наивный» способ врёт.

1. **Общая `sum` без защиты — НЕПРАВИЛЬНО.**
   Строка `sum += a[i]` = прочитать `sum`, прибавить, записать обратно. Две нити могут
   прочитать одно и то же старое значение и затереть прибавку друг друга. Поэтому
   результат каждый раз **разный и меньше** `n`. Это и есть гонка данных.
2. **`reduction(+:sum)` — ПРАВИЛЬНО.** У каждой нити появляется своя копия `sum`,
   а в конце OpenMP сам складывает все копии. Быстро и безопасно.
3. **Локальная сумма + `atomic`.** Каждая нить копит свою `local_sum`, а в общую `sum`
   добавляет один раз через `#pragma omp atomic` (атомарная, «неделимая» операция).
4. **Локальная сумма + `critical`.** То же, но вместо `atomic` используется
   `#pragma omp critical` — блок, в который одновременно может войти только одна нить.

> **Важно:** перед каждой новой параллельной областью обнуляйте `sum = 0`.
> `atomic` быстрее `critical`, потому что защищает одну операцию, а не целый блок.

## Лаба 3. Максимум и минимум вектора (файл `3.cpp`)

**Цель:** найти max и min в большом векторе, чтобы каждая нить хранила свои локальные
значения, без общего доступа к общим max/min.

Ключ — `reduction(max:vmax) reduction(min:vmin)`: каждая нить ищет максимум/минимум
на своём куске, потом OpenMP выбирает общий максимум и минимум. Общие переменные
при этом никто не трогает одновременно — требование задания выполнено.

Схема замера времени для 1..10 нитей:
```cpp
double t0 = omp_get_wtime();
#pragma omp parallel for num_threads(threads) reduction(max:vmax) reduction(min:vmin)
for (...) { ... }
double t1 = omp_get_wtime();
// время = t1 - t0
```
Правильность проверяем на 10 элементах, время меряем на ≥ 1 000 000 элементов
(в коде 20 млн). Программа печатает: число потоков и время.

## Лаба 5. Число π (файл `5.cpp`)

**Цель:** вычислить π через интеграл методом прямоугольников.

Формула (из задания):
```
pi ≈ (1/N) * Σ 4/(1 + x_i²),   где x_i = (i + 0.5)/N,  i = 0..N-1
```
Смысл: площадь под кривой `4/(1+x²)` на отрезке `[0,1]` равна π. Делим отрезок на `N`
узких прямоугольников, складываем их площади. Чем больше `N` — тем точнее.

Распараллеливаем сумму через `#pragma omp parallel for reduction(+:sum)`.
После вычисления сравниваем с `M_PI` из `<cmath>` и сравниваем время на **1 нити**
и на **максимуме нитей** (`omp_get_max_threads()`), считаем ускорение.

> `i` и `N` большие — берём тип `long long`.

## Лаба 6. Перемножение матриц (файл `6.cpp`)

**Цель:** `C = A × B` для квадратных матриц, посчитать эффективность.

Элемент `C[i][j]` = сумма `A[i][k]*B[k][j]` по всем `k`. Распараллеливаем **внешний**
цикл по строкам `i`: `#pragma omp parallel for` — каждая нить считает свои строки
результата. Нити не мешают друг другу, т.к. пишут в разные `C[i][j]`.

**Эффективность** = `t1 / t`, где `t1` — время на 1 нити, `t` — на `n` нитях.
Правильность — на матрицах 5×5 (умножаем на единичную матрицу, должно получиться то же).
Замеры — на матрицах ≥ 800×800. Программа печатает: потоки, время, эффективность.

## Лаба 7. Замки / locks (файл `7.cpp`)

**Цель:** то же суммирование, но защита общей переменной сделана **замком** вручную.

Замок (`omp_lock_t`) — это «ключ», который в один момент держит только одна нить.
Четыре шага:
```cpp
omp_lock_t lock;
omp_init_lock(&lock);      // 1) создать
...
omp_set_lock(&lock);       // 2) захватить (ждём, если занят)
sum += local;              //    безопасно меняем общую переменную
omp_unset_lock(&lock);     // 3) освободить
...
omp_destroy_lock(&lock);   // 4) уничтожить
```
Есть ещё `omp_test_lock()` — пробует захватить замок **без ожидания** (возвращает 1/0).

> **Номер варианта задания берётся у преподавателя.** В `7.cpp` показан вариант №1
> (сумма массива из 10 000 элементов). Другие варианты (чётные числа, максимум,
> факториалы, банковский счёт и т.д.) делаются по той же схеме: общую переменную,
> в которую пишут все нити, оборачиваем в `omp_set_lock` / `omp_unset_lock`.

## Лаба 8. Калькулятор на секциях (файл `8.cpp`)

**Цель:** два потока-«собеседника» через `sections` — «клиент» шлёт команды,
«сервер» их выполняет. Общение — только через общие переменные.

- `#pragma omp parallel sections num_threads(2)` создаёт 2 нити;
- каждая `#pragma omp section` — свой кусок: одна секция клиент, другая сервер;
- связь через общие переменные: буфер команды `cmd`, результат `res` и флаги
  готовности `cmd_ready` / `res_ready` / `finished`.

Логика «туда-обратно»:
1. клиент кладёт строку в `cmd`, ставит `cmd_ready = true`;
2. сервер видит флаг, разбирает `"A op B"`, считает, кладёт в `res`, ставит `res_ready = true`;
3. клиент видит `res_ready`, печатает результат и шлёт следующую команду.

Слово `res` в команде означает предыдущий результат (сначала `res = 0`). Разбор строки —
через `sscanf(cmd, "%s %c %s", a, &op, b)`. `#pragma omp flush(...)` нужен, чтобы запись
одной нити стала видна другой.

Для массива из задания `{"5 + 3", "res / 2", "24 / res", "res * res", "res - 6"}`
пошагово: `8 → 4 → 6 → 36 → 30`. Итог: **res = 30**.

## Шпаргалка: какую директиву когда брать

| Задача | Инструмент |
|---|---|
| Просто завести несколько нитей | `#pragma omp parallel` |
| Поделить цикл между нитями | `#pragma omp for` (или `parallel for`) |
| Сложить/найти max/min по всем нитям | `reduction(+:x)`, `reduction(max:x)`, `reduction(min:x)` |
| Защитить одну операцию над общей переменной | `#pragma omp atomic` |
| Защитить целый блок кода | `#pragma omp critical` |
| Ручная блокировка «ключом» | `omp_set_lock` / `omp_unset_lock` |
| Разные куски кода на разных нитях | `#pragma omp sections` + `#pragma omp section` |
| Код только для мастера | `#pragma omp master` |
| Замер времени | `omp_get_wtime()` |
